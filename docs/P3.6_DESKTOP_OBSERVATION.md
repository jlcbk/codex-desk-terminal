# P3.6 桌面会话观察——最终结论与 ZCode 适配依据

日期：2026-09-12。本文档综合 P0.2 本机探针 + 外部 Codex 调研报告（`/Users/cui/Documents/Codex/2026-09-12/hi/outputs/codex-session-observation-research.md`），作为后期 ZCode 适配开发的架构决策依据。

## 1. Codex 桌面版旁听——最终裁定：blocked，无近期时间表

| 排查路径 | 结论 | 证据 |
|---|---|---|
| 桌面私有 stdio 接入 | ✗ 不可行 | 桌面启动 `codex app-server --listen stdio://`，无外部连接点（P0.2 + 调研报告 §1） |
| 共享 daemon | ✗ 当前不可用 | npm 安装版无 standalone 路径；standalone 版曾有 `CODEX_APP_SERVER_USE_LOCAL_DAEMON=1` 但已有回归（issue #41014） |
| `--listen unix://` | ✓ 仅限自启动会话 | 适用于"由 Bridge 启动的会话"（我们已有的 bridge-owned 路径），不适用于已运行的桌面会话 |
| URL Scheme / AppleScript | ✗ 不可行 | 仅用于打开/导航线程，无结构化状态 API |
| 注入/拦截 Electron IPC | 不推荐 | 版本脆弱、隐私风险、不可维护 |

**官方时间表**：无承诺日期、无 milestone。不作为近期依赖。

## 2. 可行的 Desktop 镜像方案（Codex 侧）

调研报告推荐的最小可行架构（社区项目 m5stack-codex-companion 已验证）：

```
ChatGPT Desktop
  └─ ~/.codex/sessions/*.jsonl → 只读观察器 → 状态推断 → Bridge → ESP32

独立短生命周期 App Server
  └─ account/rateLimits/read → 额度通道 → Bridge → ESP32 USAGE 页

可选：OTel collector / notify / hooks → 补充 turn/tool 信号
```

**限制**：JSONL 观察器可推断 `working`/`done`/`error`，但**不能精确区分 `waiting approval`**——需要明确出现 approval 证据才设置。文件停滞时显示 `unknown/stale`。

## 3. ZCode 适配——架构优势分析

### 3.1 ZCode vs Codex 关键差异

| 维度 | Codex | ZCode | 对适配的影响 |
|---|---|---|---|
| 会话文件 | `~/.codex/sessions/*.jsonl`（近实时，但无结构化状态标记） | `~/.zcode/cli/agents/sess_*/`（**实时追加，含工具调用结构**） | ZCode 的 JSONL 信息量更大 |
| Hooks | PreToolUse/PostToolUse/PermissionRequest 等，command hook 收 JSON stdin，可 curl 转发 | UserPromptSubmit/SessionStart 等（**需验证完整清单**），结构类似 Claude Code | 若 ZCode 支持等价 hooks → 可主动推送 |
| 独立 app-server | 有（可 `--listen unix://`） | **无**（主进程直接管理） | ZCode 没有"bridge-owned 经 app-server"的路径；但 hooks + 文件可能等效 |
| 跨会话读取 | `thread/list`（只返回元数据） | `ReadSessionContext` 工具（**可读其他会话上下文**） | ZCode 天然支持跨会话信息访问 |
| 额度 | `account/rateLimits/read`（app-server RPC） | **未确认**（需调研 ZCode 的用量/计费 API） | 待探针 |
| 子代理 | 无直接等价 | 有（`Agent` 工具派发，output_file 落盘） | 子代理状态天然可观察（文件） |

### 3.2 ZCode 适配的推荐架构（初步设计）

```
ZCode 主进程
  ├─ 会话文件 ~/.zcode/cli/agents/sess_*/  → 实时 JSONL 观察器
  ├─ Hooks（若支持 PostToolUse 等）      → 事件推送（curl → Bridge）
  └─ 子代理 output_file                   → 子代理进度观察
                    ↓ 汇聚
              Bridge State Engine（复用现有 reducer/协议）
                    ↓ WSS / BLE
              ESP32 屏幕（复用现有固件/UI/传输）
```

**核心优势**：不需要等官方开放 daemon——hooks 和实时 JSONL 文件天然提供外部观察点。

## 7. Z1-Z6 前置核验结果（2026-09-12，主会话实测）

六项全部完成，§3.2 初步架构**成立**，且 ZCode 观察精度可超过 Codex 桌面观察（`PermissionRequest` hook 提供了 Codex 缺失的 waiting-approval 精确证据）。

| # | 结论 | 关键证据 |
|---|---|---|
| Z1 hooks | 恰好 7 个事件：`SessionStart`/`UserPromptSubmit`/`PreToolUse`/`PermissionRequest`/`PostToolUse`/`PostToolUseFailure`/`Stop`；明确**不支持** `SubagentStop`/`Notification`/`PreCompact`。matcher=大小写敏感正则（工具事件匹配工具名；`PermissionRequest` 即"等待审批"真源；`Stop` 即回合完成）。配置文件 hooks 需 `enabled: true`，插件 hooks 自动启用。**hooks 随会话启动加载，会话中新增不生效（实测）**；hook 内联执行（`async` 无运行期效果）→ 观察 hook 必须 fire-and-forget + 小 timeoutMs | 本机官方插件文档 `~/.zcode/cli/plugins/cache/.../zcode-guide/*/skills/diagnosing-hooks/SKILL.md` |
| Z2 hook stdin | 本会话无样本（hooks 不热加载）。OpenViking hook 脚本反推字段：`session_id`\|`sessionId`\|`conversation_id`；prompt 系列字段；id 系列。**架构不依赖精确 schema**：hook 只当触发器，stdin 拿 `session_id` → 定位 rollout 文件读真源。已在工作区装 dump hook（`.zcode/config.json` + `scripts/zcode_hook_dump.py` → `artifacts/zcode_hooks/dump.jsonl`），下次新会话自动采样 | `~/.openviking/agent-integrations/zcode/scripts/zcode-turns.mjs`（resolveRolloutPath/stdin 字段兼容层） |

| Z4 用量/额度 | 无计划额度 API（`~/.zcode/v2/coding-plan-cache.json` 仅 `status:"available"`）。两级替代真源：①每次调用的 `response.usage{inputTokens,outputTokens,totalTokens,cacheReadTokens,cacheWriteTokens}`（本地累计）；②限额到达以 error 形态出现：`[1308][已达到 5 小时的使用上限。您的限额将在 <时间> 重置。]`（可正则解析重置时刻）。USAGE 页方案=rollout token 累计 + 1308 错误探测 | rollout `response.usage` 实样 + agent metadata/output.txt 中 1308 错误实样 |

### 7.1 对 zcode.py 观察器的设计约束（由此轮核验直接导出）

1. **hook 只做触发器**：各事件 hook 把 `session_id`+事件名追加到落盘队列（或 curl Bridge），秒级 timeoutMs、exit 0 空输出；真源一律回读 rollout JSONL，不信任 stdin 载荷的完整性。
2. **状态映射**：`PreToolUse/PostToolUse`→working 活性；`Stop`→done；`PermissionRequest`→needs_you（精确）；`PostToolUseFailure`+rollout `error`→error；`error` 含 `[1308]`→usage_limit（带重置时间）；文件停滞超 TTL→stale。
3. **hook 安装位置**：观察全部工作区需装用户级 `~/.zcode/cli/config.json`（需 `enabled:true`，会与现有 OpenViking hooks 共存，非插件配置 hooks 无信任门）；安装脚本由 zcode.py 任务提供，本会话已验证工作区级安装格式可行。
4. **子代理进度**：轮询 `agents/sess_*/agent_*/metadata.json` 的 status/updatedAt 即可，无需 hook。
5. **样本缺口**：Z2 精确 stdin schema 待下一次新会话由 dump hook 补采样（不阻塞开发——约束 1 使 schema 仅影响触发器入参）。
